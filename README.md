## ✨ Что это

**GG Developer Studio** — это полноценная рабочая среда для Lua-разработчиков под Android, которая живёт **внутри GameGuardian** и написана на **чистом Lua**.

Больше не нужно собирать скрипт из десяти файлов в блокноте, вручную склеивать меню и ловить синтаксические ошибки уже на телефоне при запуске. Студия берёт рутину на себя: структура проекта, шаблоны, проверка кода, заметки, задачи, резервные копии — и **сборка прямо в студии** в один готовый `.lua`-файл.

> Сложные задачи. Простые инструменты.

## 🚀 Быстрый старт

**01 · Скачай файл**
Открой [файл студии на GitHub](https://github.com/nearzvx/GGDevStudio/blob/main/GG_Developer_Studio.lua), нажми **Download raw file** и скачай его на Android-устройство.

**02 · Запусти через GameGuardian**

```
Download/
└── GG_Developer_Studio.lua   →  открыть через GameGuardian
```

> Для проверки обновлений нужен доступ к публичным файлам репозитория GitHub. Скачанный Lua-файл можно запустить отдельно; архив и файл доступа не требуются.

**03 · Начни создавать**

```
Новый проект  →  добавить шаблоны  →  дописать логику  →  Build  →  готовый скрипт
```

Результат сборки, проекты и заметки лежат в выбранной рабочей папке (по умолчанию **`Download`**). Резервные копии — твоя лучшая привычка.

## 🧩 Как устроена студия

```
┌──────────────┐    ┌───────────────┐    ┌──────────────┐    ┌──────────────┐
│   Project    │ →  │   Templates   │ →  │    Check     │ →  │    Build     │
│  .ggds файл  │    │ 458 шаблонов  │    │   синтаксис  │    │  ready.lua   │
└──────────────┘    └───────────────┘    └──────────────┘    └──────────────┘
       ↑                    ↑                    ↑                   │
       └──────────  Заметки · Задачи · TODO · Бэкапы  ←───────────────┘
```

Ты добавляешь пункты и Lua-блоки, а студия собирает их в один файл с меню и служебной обвязкой. Проверка синтаксиса не гарантирует правильной работы пользовательского кода.

## 📚 Библиотека шаблонов

**458 готовых блоков**, чтобы не начинать с пустого файла:

- **Интерфейсы** — меню, списки, диалоги, уведомления
- **Строки и таблицы** — форматирование, парсинг, утилиты
- **Файлы** — чтение/запись, работа с путями, конфиги
- **GameGuardian API** — типовые обёртки и паттерны вызовов
- **Отладка и примеры** — проверки, форматирование и заготовки действий

Шаблон можно взять целиком, обрезать до нужного или использовать как шпаргалку по синтаксису.

## 🆕 Обновление 0.26

- Добавлен **GG Feature Hub** в меню инструментов: числовой поиск с выбором типа, просмотр участка файла дампа в HEX, сравнение фрагментов двух файлов, инструменты даты и времени, скорости и скачка времени, а также проверка доступности GG API.
- Поиск предлагает типы AUTO, DWORD, FLOAT, DOUBLE, WORD, BYTE, QWORD и XOR, если они поддерживаются данной версией GG. Перед очисткой и заменой результатов необходимо подтверждение. Это **не** полный список текстовых, ARM или HEX-режимов интерфейса GG; неподдерживаемые режимы не имитируются.
- Просмотр и сравнение файловых дампов выполняются без изменений файлов, до 256 байтов за запрос. Создание полного дампа памяти процесса пока не добавлено. Смещение вводится в байтах.
- Сборка проекта теперь предлагает обычный Lua, упакованный Lua или байткод. Байткод может не работать на другой версии Lua или GG. Файлы проекта `.ggds` не шифруются.
- Добавлены 8 примеров GG API; библиотека содержит 458 шаблонов. Функции времени и скорости меняют состояние выбранного процесса только после явного подтверждения.
- Реализована часть возможностей GG, не весь API: поддержка зависит от версии GameGuardian. Проверяйте работоспособность на устройстве и используйте только процессы, для которых у вас есть разрешение.

Не запускает поиск, не записывает и не очищает результаты GG. Перед сравнением убедитесь, что в GG выбран тот же процесс; адреса могут измениться. Снимок удаляется при завершении студии и не сохраняется на диск.
- Проверка внешнего текста Lua независимо от расширения и попытка загрузки совместимого байткода Lua **без выполнения**. Другие версии Lua, среды и форматы не гарантированно совместимы. При поддержке среды текст можно скомпилировать в байткод; запуск проверяйте отдельно.
- Quick Lab расширен до 250 операций: добавлены 100 параметризованных операций по обработке строк и чисел. Библиотека содержит 458 шаблонов, включая 100 соответствующих примеров этих операций. Операции длины и среза работают с байтами, не с Unicode-символами.
- Перестроено главное меню по порядку работы над проектом. При создании проекта можно выбрать пустую основу или одну из двух стартовых заготовок.
- Добавленный функционал реализован компактно; требование ровно 1000 новых строк не выполнено.

### Изменения 0.24

- Можно выбрать существующую **рабочую папку** для проектов, сборок, заметок и других файлов студии и независимо от неё — **папку модулей**, где расположен `modules.txt`.

- Установщик обновлений по-прежнему сохраняет новый Lua-файл в `Download`. Он не переносит файлы студии и не обновляет модули.

- Config Builder и Menu Builder превращают текстовые данные в Lua-блок после подтверждения; используйте таблицы внутри вставленного блока. Анализаторы выполняют эвристический поиск и не заменяют полноценный анализ или тестирование.
- Новые названия и сообщения пока преимущественно на русском. Работа с длиной, регистром и обращением текста может быть байтовой/ASCII, а не Unicode.

### Изменения 0.22

### Модули

В архиве находятся 15 отдельных Lua-модулей. Распакуй папку **`modules`** в удобное место: внутри неё должен находиться `modules.txt`, а рядом — 15 `.lua`-файлов. По умолчанию используется `Download/modules`. Примеры CSV и TSV находятся в `examples`; их можно скопировать в `Download` для теста. Запусти студию и подтверди загрузку доверенных модулей. Доступ: **Инструменты → Module Hub**. Если модулей нет, студия продолжит работать без них; в Module Hub можно посмотреть ошибки или перезагрузить модули.

| Модуль | Возможности |
|---|---|
| Project Insights | Метрики проекта и крупные блоки |
| Code Audit | Поиск текстовых признаков потенциально чувствительных операций |
| Dependency Map | Обзор буквальных вызовов `require` |
| CSV → Lua | Преобразование CSV в таблицу Lua и добавление блока в проект |
| Language Pack | Преобразование многоязычных данных TSV в таблицу переводов Lua |
| Code Search | Поиск точного текста в Lua-блоках с номерами строк |
| Title Check | Повторяющиеся и пустые названия пунктов |
| Duplicate Blocks | Точные повторы Lua-блоков |
| API Inventory | Текстовый обзор вызовов gg API |
| Marker Board | Маркеры TODO, FIXME, NOTE и HACK |
| Syntax Batch | Проверка синтаксиса отдельных блоков без запуска |
| Line Review | Строки длиннее заданного порога в байтах |
| Project Outline | Отчёт о структуре пунктов проекта |
| Config Builder | Преобразование TXT key=value в таблицу Lua |
| Menu Builder | Преобразование списка строк в меню Lua |

Анализаторы используют поиск по тексту и могут ошибаться; они не гарантируют безопасность или полноту. Данные CSV/TSV не выполняются как код; результат добавляется в проект только после подтверждения. Таблицы создаются внутри добавленного Lua-блока: используй их в этом же блоке. Все поля CSV импортируются как строки.

**Доверие:** модули — исполняемый Lua-код с теми же правами, что у студии. Они не находятся в песочнице и не проверяются сравнением с GitHub. Загружай только файлы, которым доверяешь. Основной скрипт обновляется отдельно: автообновление **не скачивает и не обновляет** папку модулей; её нужно установить или заменить вручную из релиза. При публикации размести папку `modules` и файл `modules.txt` в репозитории вместе с остальными файлами.

**Python:** GameGuardian не предоставляет обычный способ запуска внешнего Python-интерпретатора, а `os.execute` заблокирован. Python-модули напрямую здесь не работают. Вместо этого можно готовить CSV или TSV в Python и импортировать их в проект через модули. Зависимости Python в студии не нужны.

### Создание своего модуля

Добавь ID латиницей, цифрами, `_` или `-` отдельной строкой в `modules/modules.txt`, положи рядом `<ID>.lua` и перезагрузи модули через Module Hub. Максимум 32 файла из списка. Модуль возвращает `return {name = 'Название', run = function(ctx) ... end}`. `ctx.project` — копия текущего проекта или `nil`; `ctx.root`, `ctx.read_file(path, limit)`, `ctx.alert(text)`, `ctx.report(text)` и `ctx.offer_code(title, code, info)` доступны как помощники. Добавление блока требует подтверждения пользователя; модули всё равно имеют доступ к глобальным API и не изолированы.

### Публикация обновления

Загрузи новый `GG_Developer_Studio.lua` в корень ветки `main`, затем обнови `manifest.json` с тем же номером версии. Версии в файле студии и манифесте должны совпадать. После публикации GitHub может несколько минут отдавать старые файлы из кэша.
